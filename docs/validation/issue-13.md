# Issue #13：時計端点のシリアライズと独立座標照合

検証日：2026-10-27（日本時間）。対象はPythonの座標検証ツール。ブラウザ内の描画式や24秒の時間進行は変更しない。

## 問題と変更

CSSの時計は0から2πへ進む。検証ツールは従来、観測JSONの`clock_radians`をPythonの正確な`math.tau`以下に制限していた。2πを小数点以下5桁に丸めた`6.28319`を入力すると、座標照合前に範囲外として拒否した。

差は約`0.000004692820414 rad`。短辺100 CSS px・振幅100%の波形では、位相0°・左端の縦座標に約`0.000207 CSS px`の差が生じ、既定の座標許容差0.1 CSS pxより小さい。このケースはシリアライズ済み観測値を想定したPythonの再現であり、今回ブラウザから新しく採取した証跡ではない。

`clock_radians`の上限を`math.tau + 0.000005`にする。2π付近の小数点以下5桁への丸めに伴う最大0.000005 radを明示的な余裕とし、下限0は維持する。これは時計の範囲検証だけに適用し、CSS px単位の座標許容差とは分ける。他のパラメータの範囲も変更しない。

受け付けた観測時計はそのまま独立数式へ渡す。2πへのクランプや剰余処理をしないため、観測値の違いを座標誤差として引き続き検出できる。

## 回帰検査

```sh
python3 -m unittest discover -s tests -p test_coordinates.py -v
```

- 正確な0と2πを受理する。
- `6.28319`から求めた観測座標を0.000000001 CSS pxの厳しい許容差でも受理する。同じ時計で点を2πの座標へ置き換えると失敗し、暗黙のクランプを検出する。
- `6.28319`でも点を0.25 CSS pxずらすと、既定の座標許容差で失敗する。
- 負値、上限の余裕を超える値、非有限数、真偽値を拒否する。座標許容差を1000 CSS pxにしても時計の範囲検証は緩まない。
- 既存の両モデル・縦横等倍率・不正入力の検査を継続する。

上記7テストをPython unittestで確認した。実動画の24秒ループ境界、実機、OS設定、読み上げ、他ブラウザ、性能の未検証は[Issue #3](https://github.com/furukawa1020/CSS-Synthesizer-/issues/3)に残す。
