# Issue #115 — モデルの宣言と描画・独立checkerの対応

## 要件と変更

候補生成時に、モデルレジストリのID集合を独立座標checkerのSUPPORTED_MODELSと照合する。CSSの作者向け選択規則`.lab:has(#model-ID:checked)`が各モデルの同じleaf blockで--xと--yを宣言すること、未宣言のaliasがないことも検査する。接線や塗りのblockに同じselectorがあるだけでは描画bindingとして数えない。既定のリサージュは`.sample`の基底式として明示的な例外にし、基底blockの両座標宣言も確認する。コメントや引用文字列内の説明は選択規則として数えない。

検査はgallery等の静的selector aliasを生成する前の合成engine CSSへ適用する。レジストリだけ追加して既定のリサージュが別モデル名で描かれることを防ぎ、失敗時は従来どおり前回buildを保持する。

## 検証と範囲

現在の8モデル、基底式の例外、コメント・content文字列の除外、未実装モデル、欠落selector、接線だけのselector、片座標のみのblock、未知alias、独立checkerとの不一致を検査。生成失敗でも前回buildのバイト列とmtimeが保持されることを確認する。

これは作品の選択規則に対する対応ガードで、汎用CSS構文解析ではない。selectorの存在は数式が正しいこと・対応環境で描けることの証明ではない。独立数式の既知点検査とブラウザ観測を別に行う。
