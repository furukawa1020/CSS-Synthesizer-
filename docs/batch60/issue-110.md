# Issue #110 — CSS機能の構文診断

## 要件と変更

features.htmlに入力・座標描画・数値・説明表示の18条件を平面の表として生成する。各行の「構文対応／構文未対応」は実際の@supportsによるCSS表示切り替えであり、User-Agentの推測やJavaScript判定はしない。sibling関数の生成済み代替、構文の対応と実動作の違いを明示する。

@property登録・型・補間、Invoker Commands、@starting-style、@counter-style、MathML、入力・読み上げ・性能の実動作は自動判定とせず要手動確認とした。カウンターの000と平方根の表示例も確認の補助であり、合格判定ではない。各構文から一次仕様へ参照できる。

描画点のないHTMLを配布定義で0点として検査するため、audit_htmlはsamples=0を受け付ける。禁止要素・参照監査は維持し、0点のページにsampleが混入すれば不一致になる。生成・監査・ZIPの共通アセット定義へfeatures.htmlを追加し、描画画面の説明からリンクした。

## 検証と限界

条件ごとの@supportsと行ID・対応表示が生成されること、ID一意、script不在、0点監査、手動確認対象を自動対応と表示しないことをPythonで検査。build・静的監査・全unittestを実施する。実際の18条件の表示、小画面の表スクロール、読み上げは統合ブラウザQAの範囲とし、未観測の環境を合格にしない。対応表は互換性・性能・実機動作を保証しない。
