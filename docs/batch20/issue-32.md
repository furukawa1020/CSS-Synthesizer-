# Issue #32：生成失敗時に前回のビルドを残す

実装前の範囲：候補のHTML/CSSを一時ディレクトリで全て生成し、監査に成功してから`build/`へ配置する。断片の欠落、未解決トークン、CSSの欠落、監査エラーで既存の生成物を先に消さない。現在のソースと開発用ツールは引き続きJSゼロ。

配置時は旧ディレクトリを退避してから候補を移す。これは二段階のrenameであり、配信中の全リクエストや電源断に対する完全な原子性を主張しない。候補配置が失敗した場合は旧結果を戻し、退避物を消さない。

検証予定：生成途中の失敗、静的監査失敗、配置失敗のロールバック、正常な再生成と古いQAファイルの撤去をPython unittestで確認する。ブラウザの挙動や実機性能の検証ではない。

検証結果：候補生成・監査・配置失敗と正常再生成の4テスト、全35テスト、生成HTML/CSS監査、`git diff --check`が成功した。通常の例外処理で前回結果を保持する範囲を確認した。電源断や並行HTTPリクエストの完全な原子性は検証・保証していない。
