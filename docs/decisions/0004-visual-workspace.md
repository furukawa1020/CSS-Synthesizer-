# ADR-0004：作品を中心に、調整帯として操作を見せる

日付：2026-10-27（日本時間）。関連：Issue #2。これは実装上の選択であり、配色等がユーザーの好みとして承認されたという記録ではない。

## 比較と採用理由

| 案 | 主体験 | 今回の判断 |
| --- | --- | --- |
| A：作品を触る | 操作し、変化を見て、気に入った形を止める | v0.1に採用。最初の30秒の目標に直結する |
| B：式を観察する | 数式を読んで形との関係を調べる | 数式は下の解説に残す。操作前の前提にはしない |
| C：構造を組む | 信号を接続して構成を作る | 自由配線を提供できない現行範囲と合わないため見送る |

## 表現と階層

暗い描画面と明るい操作面を分け、点は一色の暖色で描く。グラデーションのカードや機材の装飾は追加しない。座標の基準円と原点の線は描画を読むための補助とする。

主操作は「形」「時間」「3つの調整帯」。時間の操作は調整帯より前に置き、スマホでも最初の描画のすぐ下に停止を見つけられる。DOM順と視覚順を揃える。PCでは描画が幅の約76%を占める。狭い画面では描画の下に操作を置く。

スクロール入力をノブやスライダーに見せない。値は大きく表示し、範囲・作用・横スクロール・左右キー・大きく送る矢印を説明する。矢印は一定の数値刻みを保証しない。

## 状態

- 通常：描画・選択中の形・時間状態・3つの値が見える。
- 調整中：フォーカス輪郭と項目名の色で対象を示す。帯を閉じて値を失わないよう、3つのscrollportは常にレイアウトに残す。
- 停止中：「時間停止中」と四角い印を表示し、形の調整は続けられる。
- スマホ：同じDOM順で縦に配置。説明は下のdetailsで開く。

文字はremで指定する。200%の文字fixtureで選択肢を折り返し、入力帯も文字に応じて高さを広げる。PCの描画領域は操作面の縦の長さに追従させず、スクロール中も描画を見られるsticky配置にする。スマホではstickyを使わない。

## 検証

[Issue #2の検証記録](../validation/issue-2.md)に4状態の画像・幅ごとの記録・座標照合・限界を保存する。実機タッチと一般端末での性能を合格にしたものではない。
