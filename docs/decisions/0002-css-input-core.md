# ADR 0002：CSSだけで入力・値・描画を接続する最小コア

日付：2026-10-26  
状態：Issue #1の技術スパイクで採用。最終UIの決定ではない。  
対象：[Issue #1](https://github.com/furukawa1020/CSS-Synthesizer-/issues/1)

## 背景

要件定義では、HTML / CSSだけで、操作した値と表示値が一致する視覚シンセサイザーを検討している。外観を作り込む前に、連続入力、数式、等方座標、時間停止の組み合わせが成立するかを確認する必要がある。

この変更は、リサージュと波形の2モデルを扱う検証画面である。配色、ブランド、作品としての最終構成、最適な描画点数は決めない。実装の範囲は[数理モデル](../math-and-input.md)と[技術検証計画](../technical-plan.md)に対応させる。

## 決定

### 1. ブラウザの実行コードと開発用コードを分ける

ブラウザへ配布するのはHTML / CSSのみとする。座標計算、入力値の変換、時間の進行、モデル選択はCSSとHTMLのネイティブ要素で実装する。JavaScript、Canvas、SVGの信号描画、ポリフィルで不足機能を補わない。

Node.jsは反復するHTMLの生成、静的監査、テスト、ローカル配信にだけ使う。生成したHTMLへNode用のコードや検証用スクリプトを混入させない。96 / 192 / 384点のページは比較用であり、点数の最適化や性能合格を意味しない。

### 2. 表示と計算に、同じ整数の有効値を使う

スクロールから得る生の値と、モデルへ渡す有効値を分離する。`@property`で登録した整数Qを共通の情報源とする。

| パラメータ | 整数の有効値Q | 描画に渡す値 | 表示 |
| --- | --- | --- | --- |
| 反復k | 生のk × 100を最も近い整数へ丸める | Q / 100 | 小数2桁 |
| 位相φ | 生の位相を最も近い整数へ丸める | Q × 1deg | 整数degree |
| 振幅A | 生のA × 100を最も近い整数へ丸める | Q / 100 | 整数% |

kの表示は、Qの整数部と小数部を分け、`counter()`と`decimal-leading-zero`で組み立てる。表示用だけを丸めて、描画に別の連続値を渡す実装にはしない。

小数2桁は表示と計算の精度であり、すべての入力方法で0.01ずつ動かせるという保証ではない。ネイティブスクロールの移動量や端末の入力解像度は別に評価する。

### 3. 描画領域の短辺を両軸の倍率に使う

描画領域には明示的な幅・高さと`container-type: size`を設定する。正規化座標x/yの両方に`44cqmin`を使い、中心からの移動へ変換する。

横と縦に同じ長さを使うため、横長・縦長の画面で図形が意図せず引き伸ばされることを避ける。`inline-size`のコンテナだけで高さ側の基準を別の領域へ逃がさない。

`sibling-index()` / `sibling-count()`が使える場合はサンプルの順序と個数をCSSで求める。未対応時に備え、ビルドで生成したインデックスと個数も保持する。どちらの場合もuは0〜1となり、同じモデルの式へ入る。

### 4. 初期位置の設定と、操作後の値の保持を分ける

入力帯は通常の横スクロール領域として扱う。初期目盛りの`scroll-initial-target: nearest`で基準値の位置を設定し、スクロール領域の`scroll-snap-type`は`none`とする。

CSS Scroll Snap Level 2の現行草案では、初期位置は対象要素へのscroll-into-view位置から求める。継続的なスナップを有効にすることは、この初期位置アルゴリズムの条件ではない。

`proximity`は、近くの目盛りへ吸着するかをブラウザが判断する。連続値を任意位置で保持する今回の入力では、短い矢印操作の後に近傍目盛りへ戻される挙動を避ける必要がある。初期化後に時間差でスナップを外す処理や、フォーカス中だけ外す処理は採用しない。

初期値はk=3.00、φ=90°、A=80%とする。履歴の戻る等でブラウザがスクロール位置を復元した場合は、その位置から有効値を算出する。「再読み込みで必ず初期値に戻る」とは案内しない。

### 5. 生成した＋−ボタンを精密なステップ入力と称さない

`::scroll-button()`はブラウザが生成するスクロール操作であり、基本の移動量はスクロール領域の約85%である。スナップを外した状態では、次の整数目盛りへ必ず移動するわけではない。

したがって、＋−を「反復を1増やす」「位相を1°変える」「次の目盛りへ送る」とは説明しない。値を大きく動かす操作として扱い、帯・スクロールバー・キーボードの実挙動と合わせて評価する。

### 6. 時間制御は3状態にする

時間の扱いを、ネイティブのラジオボタンで明示する。

| 選択 | 通常の端末設定 | 動きを減らす設定 |
| --- | --- | --- |
| 端末設定に従う | 自動時間を進める | 自動時間を停止する |
| 再生 | 自動時間を進める | 利用者の明示操作として時間を進める |
| 停止 | 自動時間を停止する | 自動時間を停止する |

単一のチェックボックスに端末設定と利用者の意思を重ねると、見えている選択状態と実際の再生状態が食い違いやすい。端末設定と明示的な再生・停止を分けることで、`prefers-reduced-motion`の尊重と、利用者が選んだ動作の意味を区別する。

停止するのは時間位相tのアニメーションだけとする。入力用の3つのスクロールタイムラインは動作させ、停止中も形を調整できるようにする。再開は停止したtから続ける。

この表は実装方針であり、OS設定変更を含む全状態の実機検証結果ではない。端末設定を変更したときの確認結果は別の検証記録へ残す。

## 対応範囲と制限

- 最初の検証対象は現行の安定版Chrome / Edge。確認したブラウザの正確なバージョンと環境は検証記録に残す。
- CSSの構文が`@supports`で認識されても、操作・描画・アクセシビリティが期待どおり動く証拠にはならない。
- 連続入力に必要な機能が不足する場合は入力帯を表示しない。描画の基盤自体が不足する場合は、図形の表示を保証せず説明を表示する。
- 表示値はCSS生成テキストを使う。読み上げでの現在値の把握や更新通知は未検証であり、アクセシブルな数値入力が完成したとは扱わない。
- 実機タッチ、異なるブラウザ、OSの動きを減らす設定、200%文字拡大、密度ごとの性能は後続の検証対象とする。未実施の項目を合格にしない。
- JavaScriptを配信しないことや、`transform`を使うことを、低負荷・高速・GPUのみの処理の根拠にしない。
- HTML / CSSの静的ガードは、このプロジェクトの成果物の条件を確認するもの。汎用サニタイザーでも、CSP下での実ブラウザ検証の代替でもない。

## リサイズ時に入力値を保持する

入力の総移動距離は画面幅の倍数にせず、k=2800px、位相=1440px、振幅=1500pxとする。各目盛りの矩形は表示幅を持たせ、配置間隔を固定長にする。これによりscroll-initial-targetで初期値へ移動でき、表示幅が変わっても同じスクロール位置から同じ有効値を得る。キャプチャ前後の幅変化でも値を保持することを検証した。
