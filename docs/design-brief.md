# デザインブリーフ draft

## 問題の定義

前作は、使い方より「機材らしさ」を先に決めた。直接触れないノブ、極小の英語、架空の商標や型番は、模様を作るという目的に寄与していなかった。今回は配色を変えるだけの作り直しにしない。

## 比較する3案

| 案 | 主体験 | 画面の構成 | 主なリスク |
| --- | --- | --- | --- |
| A：作品を触る | 変化を感じながら模様を作る | 大きな描画、必要な操作だけ。説明は必要時に開く | 隠しすぎて操作を発見できない |
| B：式を観察する | 数式と形の関係を理解する | 式と描画を並べ、操作の作用を示す | 学習ツールになり、鑑賞性が弱くなる |
| C：構造を組む | 発振や変調を組み合わせる | 信号の流れと有限の接続選択 | 自由な配線ができるように誤認させやすい |

**v0.1では実装判断としてAを採用した。** [ADR-0004](decisions/0004-visual-workspace.md)に比較と採用理由、[検証記録](validation/issue-2.md)に実装した4状態を残す。ユーザーの好みとして承認されたという意味ではない。

## 構成案Aの原則

- 最初に作品が見える。紹介文を読んでから作品へスクロールする構造にしない。
- 主な操作はモデル、形の調整、時間停止。補助設定を初回画面に並べない。
- 調整帯は調整帯として描く。見た目だけのノブ、触れない配線、無意味なLEDを置かない。
- 主要な操作名は日本語。英語は意味が必要な場合だけ補助として使う。
- 通常状態と操作中で情報密度を変える。触っていないときは描画を邪魔せず、調整中は対象と値を読める。
- 「手作り感」を根拠のない装飾や不揃いなレイアウトで作らない。文字の大きさ、余白、選択状態、動きに一貫性を持たせる。
- 背景色、線の色、線幅、発光の有無、書体、作品名は未決定。ワイヤーの白黒は配色提案ではない。

## 4つの状態

[構成比較用ワイヤーフレーム](design/wireframes.svg) は以下を示す。作り込んだUIでも実装でもない。

1. 通常：描画を主役に置き、モデル選択と停止操作を見つけられる。
2. 調整中：一つの調整帯を開き、名称・値・範囲を読みながら変更する。
3. 時間停止中：停止を明示。編集できることと、再開の入口を残す。
4. スマホ：描画を上、最低限の操作を下に置く。横スクロール入力とページの縦スクロールを混線させない。

## 判断のチェック

| 問い | 不合格の例 |
| --- | --- |
| 何を触ると何が変わるか分かるか | 触れないノブ、説明のない略号 |
| 描画より装飾が目立っていないか | 巨大な架空ブランド、ヒーローコピー |
| 状態を読めるか | 発光色だけで選択、停止してもボタン名が同じ |
| 小さい画面で本当に使えるか | 8pxのラベル、小さい＋−、値が隠れる |
| 技術の説明は正確か | 表示と内部値が違う、全モデルを同じ比率で説明 |

実装後も、構成と操作の問題を装飾で隠さず、観測とユーザーの反応から修正する。
