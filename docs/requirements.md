# 要件定義 draft 0.1

作成日：2026-10-26。状態：レビュー用草案。実装済み・ユーザー承認済みを意味しない。

## 1. 出発点

ユーザーは、最新の素のHTML / CSSによってどこまで表現と操作が可能かを探り、CSS視覚シンセサイザーを作ると決めた。最初の試作は、要件を詰めずに外観を作り、UIがAI的で雑だと指摘された。本リポジトリでは、目的、数理モデル、入力、状態、画面、検証を先に決める。

## 2. 主目的と対象

**P-01・提案：利用者がパラメータを変え、変化の関係を掴みながら、気に入った模様を見つけて止められること。**

最新CSSの技術実証はこの体験を支える副目的とする。機能名を並べるために操作を足さない。音声シンセサイザーではなく、最初の範囲では音を出さない。

想定利用者は「図形・動き・ブラウザ表現に興味があり、コードを書かずに触りたい人」。専門的な数式の理解は初回操作の前提にしない。開発者は必要なときに式とソースを参照できる。

### 最初の30秒で成立させたいこと

1. 現在の形と、操作できる箇所が分かる。
2. 一つの値を変えると、対応する形の変化を見分けられる。
3. 気に入った形で時間を止め、止めたまま調整できる。

これは達成目標であり、利用者テスト済みという主張ではない。

## 4. 機能要件の提案

以下のF/N/D/T要件は実装に向けた提案である。変更可能であり、ユーザー確定要件と区別する。

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| F-01 | 必須 | リサージュ・波形・花弁・渦巻き・合成軌道の5モデルを選べる | 選択状態と表示される式・描画が一致する |
| F-02 | 必須 | 各モデルの構造、位相、振幅を調整できる | 名称・単位・範囲が数式と対応し、入力の全範囲に意味がある |
| F-03 | 必須 | 時間の進行を停止・再開できる | 停止後に自動時間が変わらず、再開で続きから動く |
| F-04 | 必須 | 停止中もパラメータを編集できる | 「時間停止」と「全操作停止」を混同しない |
| F-05 | 必須 | 調整対象と現在値を確認できる | 入力に使う値と表示値が定義した精度で一致する |
| F-06 | 必須 | 日本語だけでも基本操作を理解できる | 英語の装飾ラベルを読まなくても一連の操作を完了できる |
| F-07 | 必須 | 式と使っているCSS機能を参照できる | 各説明から数式・実装箇所・検証結果を辿れる |
| F-08 | 必須 | 非対応時に可能な操作を正しく示す | 動かない操作を動くように表示しない |
| F-09 | 後続 | 花弁・軌道などのモデルを追加する | 2モデルの数理・入力・検証が成立した後に判断する |
| F-10 | 後続 | 参照状態へ戻す操作を提供する | フォームだけでなくスクロール入力も実際に戻せる方法が確認できた場合に採用する |

色、発光、グリッド、速度、点数の切り替えは、最初から必須機能にしない。必要性が出た場合に追加し、主操作を埋もれさせない。

## 5. 非機能要件

| ID | 要件・目標 |
| --- | --- |
| N-01 | 実行時コードはHTML / CSSのみ。現在の開発ソースにもJS/TS・Node依存を含めない。Python標準ライブラリは開発時だけ使用する |
| N-02 | PCのマウス・トラックパッド・キーボードで、選択→調整→停止→再開を完了できる |
| N-03 | スマホで描画・主要操作が使え、意図しないページ横スクロールが発生しない |
| N-04 | フォーカスが見え、主要タッチ領域は44×44 CSS px以上を目標にする |
| N-05 | 操作説明と主要ラベルは14px以上を基本に設計し、文字拡大200%で操作や値を失わない |
| N-06 | 操作に必要な通常文字はコントラスト4.5:1以上を目標にする。色や発光だけで選択状態を伝えない |
| N-07 | prefers-reduced-motionでは自動再生を停止する。明示的な開始が可能かはスパイクで決める |
| N-08 | データ送信・トラッキング・外部フォント・ログインを作品の動作条件にしない |
| N-09 | 描画の座標系は縦横で等倍率とする。画面比率で円が意図せず楕円にならない |
| N-10 | JSゼロを高速性の証拠にしない。基準環境を記録してフレーム時間と操作遅延を測る |

性能の暫定目標：基準PCで30秒の描画中、フレーム間隔のp95が33.3ms以下。画面に反映される操作応答はp95 100ms以下。基準端末・測定方法をスパイクで決めてから評価する。まだ測定していない。

## 6. デザイン要件

| ID | 要件 |
| --- | --- |
| D-01 | 作品を主役にし、操作はその変化を理解するために配置する |
| D-02 | 操作できるように見えるものは、その見た目に対応する方法で操作できる |
| D-03 | スクロール入力ならスクロールする帯として見せる。回せないノブで覆わない |
| D-04 | 架空の商標・型番・シリアル番号・装飾的なネジ・意味のない技術標語を入れない |
| D-05 | ヒーロー、機能カード、ブランド紹介を、操作画面の上に置かない |
| D-06 | 常時表示は「モデル」「形の調整」「時間停止」を中心とし、補助情報は必要時に開く |
| D-07 | 暫定案AではPCの主要領域の75%以上を描画に配分する。これは好みの確定ではなく構成比較の基準 |

## 7. 対応範囲と非対象

まず現行安定版Chrome / Edgeを検証対象とし、検証時の正確なバージョンを記録する。Safari / Firefoxは機能別に確認し、同等動作を事前に約束しない。

最初の範囲に含めないもの：音声生成・音声入力、自由なノード配線、自由ドラッグ、画像・動画書き出し、永続保存、アカウント、クラウド同期、SNS共有、外部センサー連携。

ビルド時に反復HTMLを生成することは許容案。ただし生成手段とブラウザ内の実行コードは区別する。生成言語や点数は未決定。
