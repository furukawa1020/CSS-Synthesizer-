# Issue #74：CSSエスケープの参照監査

## 要件

この作品が使う`url(...)`と引用符付き`@import`について、関数名・規則名・URL値にCSSエスケープが含まれていても既存の外部参照判定へ渡す。コメントと説明用の文字列はリソースとして扱わない。実行時・開発時ともJavaScriptは追加しない。

## 変更

`tools/css_resources.py`はCSSの識別名・文字列・URL値を区別して読み取り、各値のエスケープを復号する。1〜6桁の16進数と終端空白、単一文字エスケープ、文字列の行継続に対応する。CSS全体を先に復号しないため、値の中のエスケープされた引用符を新しい文字列境界と取り違えない。

既存の外部URL、`javascript:`、SVGデータURLの判定方針は維持し、復号した値をその判定へ渡す。`style`属性や`style`要素も同じ経路で検査する。

## 検証

Python 3のunittestで、新規5テストと既存13監査テストを実行し成功。エスケープした`url`・`@import`・スキーム、SVGデータURL、引用符、行継続、URL中のエスケープした閉じ括弧を確認した。コメント・`content`文字列・ローカル参照・通常の`calc()`を許可する回帰例も確認した。

現行の7 HTML・2 CSSを生成し、全ファイルの監査が成功した。

## 範囲と制限

これは作品専用の静的ガードであり、CSS構文全体の妥当性判定、全てのCSSリソース構文の実装、任意のCSSを安全化するサニタイザーではない。規則の適用条件や実際のブラウザ通信を判断するものでもない。

識別名・文字列・URL内のエスケープの扱いは、[CSS Syntax Module Level 3](https://www.w3.org/TR/css-syntax-3/#consume-escaped-code-point)の字句規則を参照した（2026-10-29・日本時間）。
