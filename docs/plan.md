# 作業計画と現在地

## 現在地

要件定義 draft 0.1に基づき、[Issue #1](https://github.com/furukawa1020/CSS-Synthesizer-/issues/1)の入力・数理コアを実装。Chromeでの照合結果は[検証記録](validation/issue-1.md)に記載。最終UI・配色は未決定で、[Issue #2](https://github.com/furukawa1020/CSS-Synthesizer-/issues/2)として分ける。実機・性能は[Issue #3](https://github.com/furukawa1020/CSS-Synthesizer-/issues/3)で扱う。

## 順序

| 段階 | 成果物 | 次へ進む条件 |
| --- | --- | --- |
| 0. 要件・設計 | 目的、範囲、数式、入力、4状態、検証条件 | 仮定と合意を区別し、UIの方向と純CSSの条件に未整理の矛盾がない |
| 1. 技術スパイク | S-01〜06の最小検証と記録 | 必須操作が成立するか、代替案と制約を説明できる |
| 2. 描画コア | 等方座標の2モデル、入力との接続 | 数式・値・表示が受け入れ条件に一致する |
| 3. 操作と構成 | 選んだUI案の通常・操作中・停止中・スマホ | 入力手段と見た目が一致し、キーボード/タッチが成立 |
| 4. 表現の仕上げ | 線、色、余白、文字、動き | 構成の問題を装飾で隠していない |
| 5. 検証・配布 | 受け入れ結果と配布物 | 未検証項目と制限を明示し、JSゼロ等の主張を成果物で確認 |

各段階を実装量やコミット数で完了にしない。無関係な機能を大量に足して進捗としない。

## 直近で詰める判断

1. 主体験：作品を触る／式を観察する／構造を組む。
2. UI方向：暫定Aの構成を採用するか、別の構成にするか。
3. JSゼロの範囲はユーザー指定で確定。現在のソース・開発用ツール・配布物のすべてを対象とする（Issue #7）。
4. S-01〜03の結果から、連続入力を主操作として使えるか決める。

ユーザーに同じ質問を繰り返さない。無回答を承認にしない。独立して進められる検証と、好みで大きく変わる本実装を分ける。

## 今回のやり直しで扱わないもの

旧試作の削除、旧配信先の変更、作品のデプロイ、音声機能、GitHub以外の既存プロジェクト変更。
